# Audit Data Checker

> สถานะใน workspace นี้: มี `data/sample.xlsx`, `data/sample.csv`, `data/EXPECTED.md` และชุดทดสอบครบแล้ว ตัวสร้างข้อมูลทำงานได้โดยไม่ดาวน์โหลด dependency แต่ยังไม่มี bundle จริงของ SheetJS/Chart.js ใน `vendor/` จึงยังใช้งานหน้าเว็บไม่ได้ คำสั่ง `npm test` ตรวจฟังก์ชันและตัวอย่างจริงได้โดยไม่ติดตั้งแพ็กเกจ และแสดงการข้าม 5 กรณีที่ต้องใช้ SheetJS อย่างชัดเจน ดูผลที่รันจริงใน `TEST-RESULTS.md` ขั้นตอนบนเครื่องท้องถิ่นคือ `npm run vendor` → `npm run generate-sample` → `npm test` → `npm run serve`

เว็บไซต์ภาษาไทยสำหรับช่วยผู้สอบบัญชีค้นหา **รายการที่ควรสอบทาน** ในสมุดรายวัน ใบแจ้งหนี้ AP/AR และใบสำคัญจ่าย ก่อนเริ่มทดสอบรายละเอียด ผลตรวจเป็นข้อสังเกตเพื่อสอบถามและติดตามเอกสาร ไม่ใช่ข้อสรุปว่าข้อมูลผิดหรือมีการทุจริต

**ข้อมูลของคุณถูกประมวลผลในเบราว์เซอร์เท่านั้น ไม่ถูกส่งออกไปที่ใด**

เว็บไซต์ใช้ HTML, CSS และ JavaScript ES modules ไม่มีบัญชีผู้ใช้ ฐานข้อมูล หรือบริการเบื้องหลัง ไม่มี analytics และไม่ส่งข้อมูลที่นำเข้าออกไปภายนอก เว็บไซต์อ้างอิง SheetJS และ Chart.js จาก `vendor/` เท่านั้น จึงไม่มีการเรียก CDN เมื่อใช้งาน ประวัติผลตรวจไม่ได้ถูกบันทึกถาวรในเว็บไซต์ ผู้ใช้ต้องเก็บรายงานที่ดาวน์โหลดเอง

## เริ่มใช้งาน

ใช้ static server ที่มีอยู่ หรือใช้ Node.js 22.22.0 ขึ้นไป (แนะนำรุ่นที่ทดสอบแล้ว 24.19.0):

เวอร์ชันที่ทดสอบจริงคือ **Node.js 24.19.0 โดยผู้พัฒนาใน workspace นี้** และ **Node.js 22.22.0 โดยผู้รีวิว** ผู้รีวิวยืนยันว่า `node --test tests/*.test.js` ด้วย process isolation ปกติได้ 59 tests / 54 pass / 0 fail / 5 skipped กำหนด `engines` เป็น `>=22.22.0` เพราะเป็นรุ่นต่ำสุดที่มีผลทดสอบยืนยัน ไม่อ้างว่าได้ทดสอบ 22.8.0

```sh
npm run serve
```

เปิด URL ที่ server แสดง ไม่ต้องติดตั้งแพ็กเกจหรือ build เว็บไซต์ การเปิด `index.html` ด้วย `file://` อาจถูกเบราว์เซอร์ปิดกั้น ES modules และไฟล์ข้อมูล จึงควรใช้ HTTP server ท้องถิ่น

1. กด **ใช้ข้อมูลตัวอย่าง** หรืออัปโหลด `.xlsx` / `.csv` หรือวางข้อความพร้อมแถวหัวตาราง เลือก worksheet หากไฟล์มีหลายแผ่นงาน
2. ตรวจตัวอย่าง 20 แถวแรก แล้วจับคู่คอลัมน์เลขที่เอกสาร วันที่ลงบัญชี และจำนวนเงิน คำอธิบายและบัญชีเป็นคอลัมน์เสริม โปรแกรมคาดเดาหัวคอลัมน์ภาษาไทยและอังกฤษ แต่ผู้ใช้ต้องตรวจให้ตรงกับต้นทาง
3. เลือกระบบปีอัตโนมัติ พ.ศ. หรือ ค.ศ. กำหนดเกณฑ์จำนวนเงินกลม และใส่จำนวนแถว/ยอดรวมที่คาดหวังจากระบบต้นทางหากมี ยอดควบคุมไม่ควรมาจากไฟล์ชุดเดียวกับที่กำลังตรวจ
4. กดเริ่มตรวจ เปิดส่วนผลตรวจเพื่อดูเลขแถวต้นฉบับ ค่าเดิม และเหตุผล ใช้คำแนะนำในแต่ละหัวข้อเพื่อสอบทานเอกสารต้นทาง
5. ดาวน์โหลดรายงาน `.xlsx` ซึ่งมีแผ่นงาน Summary และแผ่นงานผลตรวจแต่ละประเภท เลขแถวต้นฉบับรวมแถวหัวตารางไว้เพื่อย้อนกลับไปยังไฟล์นำเข้าได้

## การตรวจแต่ละประเภท

### 1. เลขที่เอกสารซ้ำ

**อาการ →** หลายแถวมีเลขที่เอกสารตรงกันหลังปรับข้อความ เช่น ตัวพิมพ์เล็ก/ใหญ่ ช่องว่าง อักขระที่มองไม่เห็น และเลขศูนย์นำหน้า

**สาเหตุ →** นำเข้าข้อมูลซ้ำ รวมไฟล์หลายรอบ หรือเอกสารหนึ่งฉบับมีหลายบรรทัดบัญชีซึ่งอาจถูกต้องตามปกติ

**วิธีแก้ →** เปิดเอกสารและวิธีสร้างเลขที่ในระบบ เปรียบเทียบกลุ่มแถวทั้งหมดก่อนตัดสินใจลบหรือรวมรายการ ผลตรวจแสดงว่าค่าเดิมต่างกันหรือไม่ การปรับข้อความใช้เพื่อเปรียบเทียบเท่านั้นและไม่เปลี่ยนต้นฉบับ

### 2. ช่องว่างในลำดับเอกสาร

**อาการ →** เลขลำดับหรือส่วนท้ายที่เป็นตัวเลขขาดช่วงภายในกลุ่มคำนำหน้า เช่น `PV-2569-0001` ถึง `PV-2569-0003` ขาดเลข 2

**สาเหตุ →** มีเอกสารยกเลิก เลขสงวน ชุดข้อมูลที่เลือกมาเพียงบางส่วน หรือการส่งออกข้อมูลไม่ครบ

**วิธีแก้ →** ตรวจทะเบียนเอกสารและเงื่อนไขการส่งออก ขอรายละเอียดเลขที่ขาด โปรแกรมแสดงช่วงที่ขาดอย่างกระชับและไม่สร้างแถวข้อมูลที่ไม่มีอยู่จริง ผลตรวจช่วงขาดจึงไม่มีเลขแถวต้นฉบับของรายการที่หายไป

### 3. วันที่วันหยุดสุดสัปดาห์ / วันหยุดราชการ

**อาการ →** วันที่ลงบัญชีตรงวันเสาร์ อาทิตย์ หรือวันหยุดที่มีอยู่ในตารางวันหยุดที่ตรวจสอบแล้ว

**สาเหตุ →** ระบบลงบัญชีอัตโนมัติ การทำงานวันหยุด การลงวันที่ย้อนหลัง หรือเลือกระบบปี/รูปแบบวันที่ไม่ตรงกับข้อมูล

**วิธีแก้ →** ตรวจวันที่เอกสาร ผู้อนุมัติ และแนวทางปิดบัญชีของกิจการ วันหยุดของแต่ละหน่วยงานอาจต่างกัน ต้องใช้ตารางที่ตรงกับกิจการและปีที่ตรวจ การลงบัญชีวันหยุดอาจมีเหตุผลตามปกติ

ไฟล์ `data/th-holidays.json` ที่ส่งมอบมี **placeholder เท่านั้น** ไม่ใช่รายชื่อวันหยุดที่ยืนยันแล้ว เว็บไซต์แสดงปีที่ครอบคลุมและเตือนเมื่อปีของข้อมูลไม่มีวันหยุดที่ยืนยันครบ ไม่มีการเดาวันหยุดจากความจำ ก่อนใช้งานจริงต้องเติมวันหยุดจากประกาศรัฐบาลหรือธนาคารแห่งประเทศไทย ตรวจวันหยุดชดเชยและวันหยุดพิเศษ แล้วบันทึกแหล่งประกาศในฟิลด์ `source` ทุกวัน

วิธีแก้ไฟล์วันหยุด: ใน `holidays` แทน placeholder ด้วยรายการที่มี `date` เป็น `YYYY-MM-DD` ปี ค.ศ., `name`, `source` เป็น URL ของประกาศจริง, `verified: true` และไม่ใส่ `placeholder: true` เมื่อเทียบรายการครบทั้งปีแล้วจึงเพิ่ม `coverageYears` เป็น `{ "year": ปีค.ศ., "source": "URLประกาศที่ตรวจแล้ว", "verified": true }` อย่ารับรอง coverage ทั้งปีจากวันหยุดเพียงบางวันที่กรอกไว้ ตรวจและเก็บประกาศฉบับที่ใช้ประกอบ working paper ด้วย

### 4. จำนวนเงินกลม

**อาการ →** ยอดเป็นพหุคูณของเกณฑ์ที่กำหนด เช่น 1,000 หรือ 10,000 บาท แถวเดียวอาจเข้าเกณฑ์ทั้งสองและปรากฏในยอดนับทั้งสองเกณฑ์

**สาเหตุ →** เงินทดรอง ประมาณการ ค่าบริการคงที่ หรือเงื่อนไขธุรกรรมปกติ

**วิธีแก้ →** เปรียบเทียบกับสัญญา ใบแจ้งหนี้ และนโยบายของกิจการ ปรับเกณฑ์ให้เหมาะกับขนาดรายการ จำนวนเงินกลมเพียงอย่างเดียวไม่ใช่ข้อสรุป โปรแกรมตรวจจำนวนเงินติดลบด้วยขนาดค่าสัมบูรณ์และไม่นับศูนย์

### 5. ตัวเลขเก็บเป็นข้อความ / อักขระที่ซ่อนอยู่

**อาการ →** จำนวนเงินเป็นข้อความ มีช่องว่างหัวท้าย NBSP (`U+00A0`) อักขระ zero-width ตัวเลขไทย หรือ comma ภายในข้อความจำนวนเงิน

**สาเหตุ →** คัดลอกจาก PDF/อีเมล ระบบส่งออกเป็นข้อความ หรือรูปแบบคอลัมน์ไม่สม่ำเสมอ

**วิธีแก้ →** เทียบค่าเดิมกับค่าที่ทำความสะอาด ตรวจรูปแบบหลักพันและทศนิยมก่อนแก้ไฟล์ต้นทาง การแปลงจำนวนเงินที่กำกวมจะไม่ถูกเดา ผลตรวจยังเก็บค่าเดิมและบอกสิ่งที่พบ

CSV ไม่มีชนิดเซลล์เหมือน Excel จึงไม่สามารถพิสูจน์ได้ว่าต้นทางเก็บตัวเลขเป็น text หรือ number การพบข้อความใน CSV บอกถึงรูปแบบไฟล์ที่นำเข้าเท่านั้น ตัวอย่าง XLSX เป็นฐานอ้างอิงสำหรับการทดสอบชนิดเซลล์

### 6. ปี พ.ศ. / ค.ศ. ปะปน

**อาการ →** คอลัมน์เดียวมีปี พ.ศ. และ ค.ศ. ปะปน แถวที่ใช้ระบบปีส่วนน้อยหรือปีที่อยู่นอกขอบเขตปรากฏพร้อมวันที่ที่แปลงได้

**สาเหตุ →** รวมไฟล์คนละระบบ รูปแบบวันที่ไม่ตรงกัน หรือพิมพ์ปีไม่ครบ

**วิธีแก้ →** เทียบวันที่ในเอกสารต้นทางและเลือกระบบปีให้ถูกต้อง ค.ศ. = พ.ศ. − 543 เมื่อคอลัมน์ผสมกัน การเลือก selector อย่างเดียวไม่ได้แก้ข้อมูลต้นทาง หลีกเลี่ยงปีสองหลักและแก้เป็นปีสี่หลักเพื่อไม่ให้ตีความผิด

### 7. ความครบถ้วนเทียบยอดควบคุม

**อาการ →** จำนวนแถวหรือผลรวมไม่ตรงกับยอดที่ใส่ จำนวนเงินบางช่องอ่านไม่ได้ จำนวนแถวถึงขีดจำกัด Excel 1,048,576 หรือพบสัญญาณว่าไฟล์ถูกตัดท้าย

**สาเหตุ →** เงื่อนไขการส่งออกไม่ตรงกัน แถวว่าง/ผลรวมท้ายตารางอยู่ในชุดข้อมูล จำนวนเงินแปลงไม่ได้ หรือระบบส่งออกติดขีดจำกัด

**วิธีแก้ →** ยืนยันขอบเขตข้อมูล วันที่ และยอดควบคุมจากระบบต้นทาง ตรวจจำนวนแถวและยอดแยกกัน ผลรวมของโปรแกรมอาจไม่ครบเมื่อมีค่าที่อ่านไม่ได้ และความตรงกันของยอดอย่างเดียวไม่รับประกันว่าทุกรายการครบ

### 8. Benford’s Law: เลขหลักแรก

**อาการ →** กราฟสัดส่วนเลขหลักแรกของจำนวนเงินต่างจากสัดส่วนที่ Benford คาดหวัง

**สาเหตุ →** ลักษณะธุรกิจ ข้อจำกัดช่วงราคา ราคาที่กำหนดตายตัว ขนาดตัวอย่าง หรือเงื่อนไขการเลือกข้อมูล

**วิธีแก้ →** ทำความเข้าใจประชากรและที่มาของข้อมูลก่อนใช้ผลเพื่อเลือกเรื่องสอบถาม ความเบี่ยงเบนเป็นเพียงข้อบ่งชี้ให้สอบทานเพิ่มเติม ไม่ใช่หลักฐานยืนยันข้อผิดพลาดหรือการทุจริต วิธีนี้อาจไม่เหมาะกับทุกชุดข้อมูล

โปรแกรมใช้เลขหลักแรกของค่าสัมบูรณ์ ข้ามศูนย์และจำนวนเงินที่อ่านไม่ได้ หากเหลือจำนวนเงินใช้ได้ต่ำกว่า 300 รายการ จะข้ามการวิเคราะห์พร้อมแสดงเหตุผล ไม่สร้างธงระดับแถวจากกราฟนี้

## ข้อมูลตัวอย่างและการทดสอบ

ข้อมูลตัวอย่าง 2,000 แถวเป็นรายการสมมติทั้งหมด ไม่มีข้อมูลของบริษัทหรือบุคคลจริง สร้างโดย seed คงที่และบันทึกแผนปลูกข้อสังเกตไว้ใน [data/EXPECTED.md](data/EXPECTED.md) และ [data/EXPECTED.json](data/EXPECTED.json) เลขแถวสำหรับผลตรวจนับจากไฟล์ต้นฉบับโดยมีหัวตารางที่แถว 1 ผลหลายประเภทอาจครอบคลุมแถวเดียวกัน จึงไม่ควรรวมยอดนับแต่ละประเภทเป็นจำนวนแถวไม่ซ้ำ

```sh
npm run generate-sample
npm test
```

ตัวสร้างใช้ seed `0x000A0D17` และเขียน CSV แบบ UTF-8 BOM เสมอ หากมี SheetJS จะใช้เขียน XLSX หากไม่มี bundle จะใช้ตัวเขียน OOXML สำหรับข้อมูลตัวอย่างโดยเฉพาะใน `scripts/fixture-xlsx.js` ซึ่งใช้ Node built-ins เท่านั้นและระบุโหมดที่ใช้ใน output ทั้งสองโหมดรักษาชนิดเซลล์จำนวนเงินข้อความ 9 แถว ฟังก์ชันนี้ไม่ถูกโหลดโดยหน้าเว็บ

ไม่ต้องติดตั้ง dependency เพื่อรันทดสอบ ใช้ Node.js built-in test runner มี unit tests สำหรับการตรวจทั้ง 8 ประเภท และ integration tests อ่านทั้ง `sample.xlsx` และ `sample.csv` เทียบกับบล็อก JSON คงที่ใน `data/EXPECTED.md` โดยตรวจว่า `EXPECTED.json` ตรงกันด้วย ค่าคาดหวังไม่ได้สร้างจากผลของฟังก์ชันตรวจ

`npm test` ใช้ `node --test tests/*.test.js` และ process isolation ปกติ ไม่มีการแชร์สถานะข้ามไฟล์ทดสอบ ใน sandbox นี้ child process ที่ใช้ pipe ถูกปฏิเสธด้วย `EPERM` ทำให้คำสั่งปกติรายงานเพียง 7 ไฟล์ ไม่ใช่หลักฐานว่ารัน assertion ครบ ผู้พัฒนาจึงตรวจเพิ่มด้วย plain Node ที่ import ไฟล์ทดสอบเดิมทั้ง 7 ไฟล์จากสคริปต์ชั่วคราวนอก repository และได้ 59 tests / 54 pass / 0 fail / 5 skipped โดยไม่แก้ assertion ดู output ทั้งสองคำสั่งใน `TEST-OUTPUT.txt`

เมื่อไม่มี SheetJS integration test ใช้ตัวอ่าน fixture ZIP/XML ที่แยกอยู่ใน `tests/helpers/` ซึ่งไม่ใช่ตัวอ่านไฟล์ของหน้าเว็บ และรันการตรวจทั้งหมดบนค่าที่อ่านจากไฟล์จริง การทดสอบเส้นทาง SheetJS ในหน้าเว็บ/การส่งออกรายงาน 5 กรณีจะแสดง `SKIP` พร้อมเหตุผล หลังรัน `npm run vendor` ต้องรัน `npm test` อีกครั้งเพื่อยืนยันกรณีเหล่านั้น โดยควรไม่มีการข้ามก่อนเผยแพร่

### บันทึกทดสอบด้วยมือ

ชุดทดสอบ Node ตรวจทั้งฟังก์ชันและเส้นทางอ่านไฟล์ → จับคู่ → ตรวจ → สร้างรายงาน การตรวจหน้าเว็บด้วยเบราว์เซอร์จริงในสภาพแวดล้อมพัฒนานี้ยังทำไม่ได้ เพราะ sandbox ปิดการเปิด socket ของ Chromium และ static server รายการด้านล่างเป็นรายการตรวจด้วยมือที่ต้องทำบนเครื่องผู้ใช้และหลังเผยแพร่ ก่อนนำไปใช้กับงานจริง

- เปิดเว็บผ่าน static server เลือกตัวอย่าง ตรวจ 20 แถวแรกและการจับคู่คอลัมน์ รันตรวจแล้วเทียบจำนวนกับ `data/EXPECTED.md`
- อัปโหลดทั้ง XLSX และ CSV วางข้อมูล CSV/TSV รวมแถวหัวตาราง เปลี่ยนคอลัมน์ที่จับคู่ และตรวจเลขแถวกลับไปยังต้นฉบับ
- ใส่ยอดควบคุมที่ตรงและต่างจากตัวอย่าง รวมกรณีศูนย์และจำนวนเงินติดลบ ตรวจความต่างและคำเตือนจำนวนเงินอ่านไม่ได้
- เปลี่ยนเกณฑ์จำนวนเงินกลม เลือกระบบปี และตรวจคำเตือนปีที่ตารางวันหยุดยังไม่ครอบคลุม
- ดาวน์โหลดรายงาน เปิดใน Excel/LibreOffice ตรวจ Summary แผ่นงานทุกประเภท ค่าเดิม เหตุผล และเลขแถวต้นฉบับ
- ใช้ Tab, Shift+Tab และ Enter เปิดคำแนะนำและส่วนผลตรวจ ตรวจ focus ที่มองเห็นได้ และลองหน้าจอโทรศัพท์แนวตั้ง
- ตรวจแท็บ Network ว่าการรันตรวจและส่งออกรายงานไม่มี request ที่นำข้อมูลออกไป ปิดเครือข่ายภายนอกแล้วใช้ static server ท้องถิ่นให้ไฟล์ในโครงการยังโหลดได้

## ข้อจำกัดและความเป็นส่วนตัว

ผลตรวจช่วยคัดรายการเพื่อสอบทาน ไม่แทนความเข้าใจระบบบัญชี เอกสารต้นทาง การประเมินความเสี่ยง หรือดุลยพินิจของผู้สอบบัญชี ข้อมูลแยกหลาย sheet หรือไฟล์ต้องตรวจตามขอบเขตที่ต้องการ การเปรียบเทียบเลขที่อาจรวมรูปแบบที่กิจการตั้งใจแยกกัน ควรตรวจกลุ่มก่อนใช้งานต่อ

ข้อมูลอยู่ในหน่วยความจำเบราว์เซอร์ ไฟล์ใหญ่ใช้เวลาและหน่วยความจำตามเครื่อง ไม่รองรับไฟล์ที่มีรหัสผ่าน และไม่คำนวณสูตร Excel ใหม่ ใช้ค่าที่บันทึกใน workbook โดยต้องตรวจความใหม่ของค่านั้น รายงานอาจมีข้อมูลอ่อนไหวเช่นเดียวกับต้นฉบับ จัดเก็บและส่งต่อตามแนวทางขององค์กร

## เผยแพร่ผ่าน GitHub Pages

1. นำไฟล์โครงการทั้งหมดรวม `vendor/`, `src/`, `data/` และ `.nojekyll` ใส่ repository โดยให้ `index.html` อยู่ที่ root
2. เปิด **Settings → Pages → Build and deployment → Deploy from a branch** เลือก branch ที่ต้องการและโฟลเดอร์ `/ (root)` แล้วกด Save
3. รอ GitHub Pages เผยแพร่และเปิด URL ของ repository ไม่ต้องมี build step หรือ environment variables
4. ตรวจการโหลดตัวอย่าง การทำงานบน path ของ repository และการดาวน์โหลดรายงานอีกครั้ง ใช้ path แบบ relative เพื่อรองรับ project Pages

การเผยแพร่หรือปรับไฟล์วันหยุดต้องจัดการผ่าน repository ตามปกติ เว็บไซต์ไม่เขียนข้อมูลกลับไปยัง server หลังโหลดไฟล์โครงการครบ สามารถใช้จาก static server ท้องถิ่นโดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต ไม่มี service worker หรือการติดตั้งแอปแบบออฟไลน์จากการเปิด URL ครั้งเดียว

## เผยแพร่ด้วย GitHub Actions

ตั้งค่าครั้งแรก:

1. สร้าง repository แบบ **Public** เพื่อใช้ GitHub Pages ฟรี แล้ว push โครงการทั้งหมดพร้อม `.github/workflows/pages.yml` ไปที่ branch `main` โดยให้ `index.html` อยู่ที่ root ต้องเก็บไฟล์ตัวอย่าง `data/` และสคริปต์ `scripts/vendor-libraries.js` ไว้ใน repository
2. เปิด **Settings → Pages → Build and deployment → Source** แล้วเลือก **GitHub Actions** วิธีนี้ใช้แทนการเลือก Deploy from a branch ข้างต้น
3. ตรวจว่า repository อนุญาต GitHub Actions จากนั้นเปิดแท็บ **Actions → Deploy to GitHub Pages** การ push ไป `main` จะเริ่ม workflow อัตโนมัติ หรือกด **Run workflow** เพื่อเริ่มเอง
4. เมื่อสำเร็จ เปิดลิงก์ของ environment **github-pages** ในหน้าสรุป workflow หรือ URL ใต้ **Settings → Pages** แล้วตรวจหน้าเว็บผ่าน URL ของ repository

Workflow ใช้ Node.js 24 เรียก `npm run vendor` เพื่อดาวน์โหลด **SheetJS 0.20.3** และ **Chart.js 4.5.1** ของจริงพร้อมใบอนุญาตและ `vendor/SHA256SUMS.txt` จากนั้นรัน `npm test` ไม่ต้อง commit bundle ที่ดาวน์โหลดจากเครื่องนี้ และไม่มี runtime CDN

ขั้นทดสอบใช้ `set -o pipefail` เพื่อไม่ให้ `tee` กลบ exit code และตรวจ summary ทั้งรูปแบบ TAP/ข้อความปกติ ต้องพบ **59 tests / 59 pass / 0 fail / 0 cancelled / 0 skipped** อย่างครบถ้วน หากมีการข้าม ล้มเหลว ยกเลิก จำนวนไม่ตรง หรือ summary ขาด/ซ้ำ จะหยุดก่อนอัปโหลดและ deploy

สร้าง `_site/` ใหม่ทุกครั้ง โดยเก็บเฉพาะ `index.html`, `src/`, `data/sample.xlsx`, `data/sample.csv`, `data/th-holidays.json`, bundle JavaScript จริงใน `vendor/`, ใบอนุญาตของไลบรารี และ `.nojekyll` ใบอนุญาตคงเนื้อหาเดิมโดยใช้ชื่อ `LICENSE-SheetJS` และ `LICENSE-Chartjs` ไม่มีนามสกุล ไม่เผยแพร่ tests, scripts, เอกสาร EXPECTED/README, รายงาน `.txt`, Git bundle หรือ ZIP และเปิด `include-hidden-files` เพื่อเก็บ `.nojekyll` ใน artifact

- [actions/checkout@v7](https://github.com/actions/checkout/releases/tag/v7.0.1)
- [actions/setup-node@v7](https://github.com/actions/setup-node/releases/tag/v7.1.0)

สิ่งที่ต้องตรวจในแท็บ Actions หลังรันจริง:

- **Vendor libraries** สำเร็จ ดาวน์โหลดทั้งสอง bundle และใบอนุญาตจริง และสร้าง `SHA256SUMS.txt` ได้ หากดาวน์โหลดไม่ได้ workflow ต้องหยุด
- **Test and require 59 passing cases** แสดงครบ 59 tests / 59 pass และ fail, cancelled, skipped เป็น 0 ทั้งหมด ห้ามถือว่าผลแบบข้าม 5 กรณีผ่านเงื่อนไขเผยแพร่
- **Stage website files** และ **Upload Pages artifact** สำเร็จ ตรวจ artifact `github-pages` ว่ามีเฉพาะรายการ `_site/` ข้างต้น รวม `.nojekyll` และไม่มีไฟล์พัฒนา/รายงาน
- **Deploy to GitHub Pages** สำเร็จและแสดง URL เปิด URL แล้วทดสอบข้อมูลตัวอย่าง อัปโหลด/วางข้อมูล กราฟ Benford และดาวน์โหลดรายงาน ตรวจบนมือถือและตามรายการทดสอบด้วยมือ
- หาก environment `github-pages` มี protection rules ที่คุณตั้งไว้ ให้ตรวจว่าการ deploy รออนุมัติหรือถูกจำกัด branch หรือไม่

ใน workspace นี้ตรวจได้เฉพาะ syntax YAML, shell, รูปแบบ trigger/permissions, รายการ staging และเงื่อนไขตรวจ summary ด้วย log จำลอง ไม่ได้รัน workflow บน GitHub ไม่ได้ดาวน์โหลดหรือสร้าง vendor bundle แทนของจริง การดาวน์โหลดจริง การทดสอบ 59 กรณีด้วย SheetJS จริง การสร้าง/อัปโหลด artifact และ URL ที่เผยแพร่ยังไม่ยืนยันจนกว่า workflow จะทำงานบน GitHub ดูข้อกำหนดการตั้งค่าจาก [เอกสาร GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## Assumptions

- แถวแรกที่มีข้อมูลของ worksheet/ข้อความเป็นหัวคอลัมน์ ตรวจครั้งละหนึ่ง worksheet และข้ามแถวที่ว่างทั้งหมด เลขแถวที่รายงานเป็นตำแหน่งเดิมก่อนข้ามแถวว่าง รองรับสูงสุด 500 คอลัมน์เพื่อจำกัดการใช้หน่วยความจำ
- ไฟล์ CSV ใช้ UTF-8 (มีหรือไม่มี BOM) ข้อมูลที่วางรองรับ CSV และแท็บ หากส่งออกด้วย encoding อื่นควรแปลงเป็น UTF-8 หรือใช้ XLSX
- รูปแบบวันที่ข้อความเป็น `YYYY-MM-DD`, `DD/MM/YYYY` หรือ `DD-MM-YYYY` ใช้วัน/เดือนแบบไทย ปีสี่หลัก รวมเลขไทย Excel date serial ใช้ระบบวันที่ของ workbook
- ปี ค.ศ. ที่ยอมรับอยู่ในช่วง 2000–2099 และ พ.ศ. ที่แปลงแล้วอยู่ในช่วงเดียวกัน ปีสองหลักไม่ถูกเดา ปีอย่าง 1900 หรือ 2900 ต้องสอบทาน วันที่ไม่ถูกต้องไม่ใช้ตรวจวันหยุด
- ตรวจระบบปีจากค่าต้นฉบับ หากจำนวน พ.ศ./ค.ศ. เท่ากันให้รายงานว่าไม่มีระบบหลักที่ชัดเจน การเลือกปีใช้ในการแปลวันที่สำหรับการตรวจอื่น
- จำนวนเงินใช้จุดเป็นทศนิยม comma เป็นหลักพันที่จัดกลุ่มถูกต้อง รองรับเครื่องหมายลบและวงเล็บเพื่อแสดงยอดติดลบ ไม่รองรับสกุลเงินที่พิมพ์ติดค่าและรูปแบบทศนิยมแบบ comma
- การเทียบยอดรวมรวมค่าทศนิยมอย่างแน่นอนก่อนปัดผลรวมครั้งเดียวเป็นสตางค์ เศษครึ่งสตางค์ปัดออกจากศูนย์ หากยอดหรือผลต่างเกินจำนวนเต็มสตางค์ที่ JavaScript แสดงได้แน่นอน (9,007,199,254,740,991 สตางค์) จะแสดงคำเตือนและไม่รับรองการเปรียบเทียบ จำนวนเงินศูนย์ไม่เข้าเกณฑ์จำนวนเงินกลมและ Benford ตัวอย่างทั้งหมดใช้ทศนิยมไม่เกินสองตำแหน่ง
- จำนวนแถวจริงของ worksheet รวมแถวหัวตารางและแถวว่าง จึงใช้ตรวจขีดจำกัด Excel เท่านั้น ไม่ใช้สรุปว่าข้อมูลถูกตัดทอน การเตือนว่าถูกตัดทอนต้องมีหลักฐานจากจำนวนรายการที่ประกาศไว้เทียบกับจำนวนรายการที่อ่านได้ หรือสัญญาณจากตัวอ่านไฟล์
- ลำดับเอกสารตรวจเฉพาะช่วงระหว่างเลขต่ำสุดและสูงสุดที่พบในแต่ละคำนำหน้า ไม่คาดเดาจุดเริ่ม/จุดสิ้นสุด ไม่ตีความปีในคำนำหน้าเป็นเลขลำดับ
- ตารางวันหยุดเริ่มต้นไม่มีวันที่ที่ยืนยันแล้ว วันเสาร์/อาทิตย์ตรวจได้เสมอ แต่การไม่พบวันหยุดราชการในปีที่ยังไม่ครอบคลุมไม่ใช่ผลยืนยัน
- XLSX ตัวอย่างเป็นชุดอ้างอิงชนิดเซลล์ CSV ใช้เพื่อทดลองนำเข้าและอาจสูญเสียความแตกต่างระหว่างตัวเลขกับข้อความที่ต้นทางเก็บไว้
- ตัวช่วยเขียน XLSX โดยไม่ใช้ dependency รองรับเฉพาะ worksheet ข้อมูลตัวอย่างและรักษาชนิด numeric/text cell เป็นทางเลือกสำหรับการสร้าง fixture ในสภาพแวดล้อมที่ดาวน์โหลดไลบรารีไม่ได้ การอ่านไฟล์และส่งออกรายงานของเว็บไซต์ยังต้องใช้ SheetJS จริง
- ยังไม่มีประวัติการตรวจหรือการบันทึก mapping ข้ามการโหลดหน้าใหม่ และไม่รวมการเชื่อมต่อระบบบัญชีภายนอก
- โปรเจกต์นี้จัดส่งเป็น repository ท้องถิ่นพร้อมใช้กับ GitHub Pages ยังไม่ได้เชื่อมบัญชีหรือ repository GitHub จึงไม่มี URL เผยแพร่จริง ขั้นตอนเผยแพร่ข้างต้นใช้ไฟล์ที่ root ได้โดยไม่ต้อง build

## โครงสร้างและสิทธิ์ใช้งานไลบรารี

`index.html` และ `src/` คือเว็บไซต์ `src/checks/` คือฟังก์ชันตรวจที่ไม่มีผลข้างเคียง `data/` เก็บตัวอย่างและตารางวันหยุด `scripts/` สร้างตัวอย่างและเปิด static server `tests/` เก็บการทดสอบ ส่วน `vendor/` เก็บไลบรารีและใบอนุญาต ดูรายละเอียดเวอร์ชัน แหล่งไฟล์ และสิทธิ์ใช้งานใน `vendor/README.md`
